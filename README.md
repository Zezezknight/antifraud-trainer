# 🛡️ Антискам-тренажер для «Авито»

> **Антискам-тренажер** — это интерактивное обучающее веб-приложение, созданное для отработки навыков безопасных сделок.

Пользователь регистрируется на платформе, выбирает сценарий и погружается в мессенджер-подобный интерфейс. Принимая решения в диалогах, он получает мгновенный фидбек, развернутый отчет об ошибках и рекомендации. 
Система геймификации (начисление очков, уровни, таблица лидеров) мотивирует пользователей соревноваться и повышать свою цифровую грамотность.

## 🚀 Быстрый старт

**Требования к окружению:**
* **Go**: `v1.26.2+`
* **PostgreSQL**: `v18.0+`

Клонируйте репозиторий и запустите проект через Docker:

```bash
git clone git@github.com:Zezezknight/avito-antifraud-trainer.git
cd ./avito-antifraud-trainer

# Настройка переменных окружения
mv backend/.env.example backend/.env

# Запуск контейнеров
docker compose up -d
```

## 🔌 API и эндпоинты

Вся интеграция с бэкендом осуществляется через REST API. Все защищенные эндпоинты требуют передачи токена в заголовке `Authorization: Bearer <JWT>`

### 🔐 Аутентификация (`Auth`)
* `POST /api/auth/register` — Регистрация нового пользователя (возвращает JWT-токен)
* `POST /api/auth/login` — Вход в систему и получение JWT-токена

### 👤 Пользователи (`Users`)
* `GET /api/users/me` — Получение данных текущего профиля (очки, статус, пройденные сценарии)

### 🎭 Сценарии и игровая механика (`Scenarios`)
* `GET /api/scenarios` — Получение списка доступных сценариев (опциональный фильтр `?role=buyer|seller`)
* `GET /api/scenarios/{id}` — Подробная информация о конкретном сценарии[cite: 2].
* `GET /api/scenarios/{id}/start` — Старт прохождения: получение стартового сообщения и вариантов ответа
* `POST /api/scenarios/{id}/step` — Совершение шага (выбор ответа) и переход к следующему узлу диалога
* `POST /api/scenarios/{id}/finish` — Завершение сценария и сохранение итогового результата

### 🏆 Лидерборд (`Leaderboard`)
* `GET /api/leaderboard` — Таблица лидеров, отсортированная по набранным очкам.

## 💡 Ключевые архитектурные решения

* **Clean Architecture:** Разделение приложения на независимые слои (Handler -> Service -> Repository), что упростило параллельную разработку в команде и изолировало бизнес-логику от внешних зависимостей.
* **Stateless JWT-аутентификация:** Использование JWT с передачей `user_id` в контексте запроса позволило не хранить сессии в базе данных и ускорить валидацию защищенных роутов.
* **Графовая структура сценариев:** Сценарии прохождения представлены в виде ориентированного графа (узлы-сообщения и ребра-варианты ответов), что позволяет легко ветвить диалоги и давать развернутую обратную связь на каждый шаг.

## ⚠️ Ограничения MVP
- Упрощенный алгоритм подсчета очков за прохождение сценария
- Фиксированный набор сценариев, отсутствие динамического конструктора
